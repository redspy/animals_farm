# 상점 설계 회의 (2026-09-15)

대상: `2026-09-15-1112-아이들-콘텐츠-후보.md`의 1순위 **A1 상점**.

> §1 가상 페르소나(창의/기획)의 산출물. 밸런스 수치·프로토콜 변경의 정합성은
> 커밋 전 CLI 교차검증으로 따로 받는다.

## 0. 이 기능이 푸는 문제

서버에 **구매 경로가 한 줄도 없다**(`sell`만 있다). 벨은 쌓이기만 하고 쓸 곳이 없어
채집·낚시·부탁이 전부 "숫자를 올리는 일"에서 끝난다. 상점은 새 재미를 더하는 것이
아니라 **이미 있는 콘텐츠 전부에 목적을 주는** 기능이다.

## 1. 스코프 — 1차에는 "옷 색"만 판다

외형은 세 축이다: `hair`(스타일, 그림), `skin`(팔레트 키), `outfit`(팔레트 키).

- **판다**: `outfit` — 팔레트에 색 키를 추가하고 화이트리스트를 넓히면 끝이라
  **스프라이트 코드가 0줄** 바뀐다.
- **안 판다(1차)**: `hair` 스타일은 그리는 코드가 필요하고, **머리색**은 프레임 캐시
  키(`look_signature`)에 새 축을 넣어야 한다 — 빠뜨리면 머리색만 다른 두 사람이 같은
  프레임을 공유한다(design.md §5가 경고한 바로 그 함정). 2차로 미룬다.
- **안 판다(영구)**: `skin` — 피부색은 "꾸미기"가 아니라 그 사람 자체다. 돈으로
  사고파는 축으로 만들지 않는다.

## 2. 가게는 누가 여는가

**해변 오두막(`beach_hut` 존, -27/13.5)에 가게 주인 NPC를 세운다.**

- 새 건물·존을 만들지 않는다(지형 작업 0). 이름 있는 지형이라 "어디 가면 산다"가 말로
  통한다.
- ⚠️ **처음에는 광장(0/-13.5)에 뒀다가 옮겼다.** 광장은 지나다니는 길이라, 땅을 탭해
  이동하려다 NPC 탭 반경(2.2) 안에 들어가면 **가게가 열려 버린다** — 2탭 테스트가
  실제로 그렇게 막혀서(이모티콘부터 연쇄 실패) 발견했다. 기존 이웃 3마리가 전부
  가장자리에 있는 것도 같은 이유였다. 대신 **스폰에서 멀어진 만큼 발견 가능성이
  떨어지므로**, 처음 접속한 아이에게 가게를 어떻게 알릴지는 뒤에 따로 볼 것.
- 종은 **너구리(raccoon)** — 팔레트에 `raccoon_body`/`raccoon_accent`만 추가하면
  고양이 실루엣에 다른 색으로 그려진다(스프라이트 코드 0줄). 기존 3마리와 구분된다.
- **가게 주인은 하루 부탁을 주지 않는다.** 한 동물이 부탁도 주고 물건도 팔면 대화창에
  버튼이 둘이 되어 아이가 헷갈린다 — 서버의 부탁 후보에서 제외한다.

## 3. 소유와 화이트리스트

지금 외형 화이트리스트는 **프리셋에서 유도한 전역 집합**이다. 여기에 "산 것"이 붙으면
**사람마다 다른 집합**이 된다.

- 서버가 `p.owned`(산 상품 id 목록)를 갖고 세이브에 남긴다.
- 허용 집합 = **프리셋 유도 ∪ 내가 산 것**. `appearance()`는 이 집합으로 검사하고,
  `welcome`의 `appearanceChoices`도 **그 사람 기준**으로 만든다.
- 저장된 `owned`에 카탈로그에 없는 id가 있어도 **지우지 않는다**(상품을 데이터에서
  잠깐 뺐다가 되돌리면 복구돼야 한다) — 쓰는 시점에 거른다. design.md §3의 규칙 그대로다.

## 4. 가격

하루 수입 감각을 기준으로 세 단계로 나눈다(조개 180, 오징어 600, 실러캔스 2500).

| 단계 | 뜻 | 가격 |
|---|---|---|
| 오늘 살 것 | 몇 번 캐면 산다 | 200~400 |
| 이틀치 | 하루 모아야 산다 | 800 |
| 모아서 살 것 | 며칠 목표가 된다 | 1500 |

1차 상품: 분홍 200 · 민트 300 · 주황 400 · 검정 800 · 금색 1500.

**인플레는 아직 걱정하지 않는다** — 지금은 소비처가 0이라 "너무 싸다"보다 "살 게
없다"가 문제다. 다 사고 나면 그때 다음 상품을 넣는다.

## 5. 서버가 판정하는 것

| 검사 | 이유 |
|---|---|
| 없는 상품 id | 클라이언트가 임의 값을 사는 것을 막는다 |
| 벨 부족 | 재화의 단일 출처는 서버다 |
| 이미 보유 | 중복 결제로 벨만 사라지는 사고를 막는다 |
| 연타(400ms) | 다른 정산 경로와 같은 규칙 |
| 가격 유효범위 | `data/shop.json`의 `limits.price`로 데이터가 소유 |

구매가 성공하면 **산 사람에게만** 응답한다(남에게 방송할 이유가 없다 — 외형을 실제로
바꾸면 그때 기존 `appearance` 방송을 탄다).

## 6. 화면

- 가게 주인을 탭하면 **가게 화면**이 열린다(부탁 대화창 대신).
- 한 줄에 상품 하나: 색 견본 · 이름 · 가격 · [사기]. 이미 산 것은 **[보유]**로 잠근다.
- 위에 **내 벨**을 크게 둔다. 아이가 "얼마 남았지"를 바로 본다.
- 산 직후 토스트로 알리고, 꾸미기 화면을 열면 그 색이 **이미 골라져 있다**(산 것을
  바로 입어 보는 것이 이 기능의 보상이다).

## 7. "됐다"의 판정 기준 (QAEngineer)

- 서버 유닛: 구매 성공(벨 차감·소유 추가) / 벨 부족 거절(벨 불변) / 이미 보유 거절 /
  없는 상품 거절 / 연타 거절 / **재시작 후 소유 유지** / 산 색이 그 사람 화이트리스트에
  들어가고 **안 산 사람에게는 안 들어간다**.
- 데이터 린트: 모든 상품의 `value`가 팔레트에 있고, 가격이 `limits.price` 안.
- 브라우저: 가게 주인 탭 → 가게 열림 → 사기 → 벨 감소 → 꾸미기 화면에 새 색이 보임.
