# 에이전트 및 모델 역할 정의서 (Agent & Model Roles Specification)

이 문서는 animals_farm(게임 프로젝트)의 기획·구현·검증·릴리즈 프로세스에 관여하는 **8인의 가상 에이전트 페르소나**, **메인 코딩 에이전트(현재 세션)**, **브라우저 서브에이전트**, 그리고 **3개의 독립된 헤드리스 CLI 프로세스**(Claude Code / Codex CLI / Antigravity CLI)의 업무 분장과 협업 규약을 규정한다.

`trading` 프로젝트(국내주식 자동매매 서버)의 개발 방식을 그대로 이식했고, 도메인 특성만 게임(실시간 렌더링, 세이브 데이터, 밸런스/재미)에 맞춰 바꿨다. 실거래 자금 대신 **플레이어 경험과 세이브 데이터 무손실**이 최우선 보호 대상이다.

---

## 0. 원칙: 가상 페르소나와 실제 멀티 CLI를 구분한다

`Agent` 툴로 만드는 서브에이전트(`fork`, `general-purpose` 등)는 전부 **Claude 모델**로 동작한다. Claude Code 안에서 "역할"을 아무리 나눠도 실제로는 하나의 모델 패밀리가 여러 페르소나를 연기하는 것이라, 서로 다른 모델의 관점 차이를 활용할 수 없고 **자기검증(self-review) 편향** 위험이 남는다.

그래서 업무 성격에 따라 두 방식을 명확히 구분한다.

- **정답이 없는 창의/기획 작업** (코어 루프 아이디어, 세계관, UX 방향, 아트 톤) → **§1의 가상 페르소나**로 충분하다.
- **정답이 있는 검증 작업** (세이브 데이터 마이그레이션 버그, 상태 동기화/경쟁 조건, 밸런스 수치의 유효범위, 스펙-구현 정합성 판정, 시크릿 하드코딩) → 반드시 **§3의 실제 독립 CLI 3종**을 Bash 서브프로세스로 직접 기동해 교차검증한다. 단 **자동 게이트(pre-commit/CI)는 상시 감지용으로 2종만 돌린다** — 어느 단계에 몇 종이 필요한지의 단일 출처는 AGENTS.md §4 표다. **특히 세이브 데이터 스키마 변경·마이그레이션·과금/재화 로직은 가상 페르소나 판단만으로 절대 커밋하지 않는다** (플레이어 진행도 손실은 되돌릴 수 없다).

| CLI | 실행 파일 | 헤드리스 플래그 | 비고 |
|---|---|---|---|
| Claude Code | `/Users/soul/.local/bin/claude` | `claude -p` | 이 세션과 별도 `--session-id`로 실행해야 컨텍스트 오염(자기검증)을 피함. 내러티브/대사 톤 같은 표현력 검증은 `--model claude-fable-5`로 교차검증 |
| Codex CLI | `/usr/local/bin/codex` | `codex exec`, `codex review` | GPT 계열, 스펙-코드 대조에 강함. 백그라운드 실행 시 stdin을 `< /dev/null`로 |
| Antigravity CLI (`agy`) | `/Users/soul/.local/bin/agy` | `agy -p --model gemini-3.1-pro-high` | Gemini 계열, 스크린샷 비교 등 멀티모달에 강함 — 게임 화면 비주얼 리뷰의 주력 |

이 3종 호출은 `scripts/cli-runner.js`(`runClaude` / `runCodex` / `runGemini` / `runPanel`)로 공통화되어 있다. `npm run panel "프롬프트"`로 3종 병렬 기동 후 리포트를 비교할 수 있고, 한 CLI가 인증/쿼터로 실패해도 나머지 결과는 살린다(fail-open, §4와 동일 정책).

## 1. 가상 에이전트 페르소나 (기획 및 아키텍처)

> **적용 범위**: 아래 8인은 전부 이 세션(Claude)이 연기하는 가상 페르소나다. **창의/기획 단계에서만** 쓰고, 버그 원인 판정·세이브 데이터 정합성·성능 수치 같은 정답이 있는 작업의 최종 근거로 쓰지 않는다.

### 👑 PMOrchestrator (프로젝트 매니저)
- 의사결정 회의 조율 및 아키텍처 명세 설계.
- 각 전문가 의견을 취합해 최종 방향을 투명한 근거와 함께 선정하고, 스코프 팽창을 차단.

### 🎮 GameDesigner (코어 게임 디자이너)
- 코어 루프(무엇을 반복하면 재미있는가), 메커닉, 진행/보상 구조 설계.
- 각 기능이 코어 루프를 강화하는지 판정 — 재미에 기여하지 않는 기능은 제안 단계에서 잘라낸다.

### 🗺️ LevelDesigner (레벨/콘텐츠 디자이너)
- 스테이지 구성, 난이도 곡선, 신규 메커닉 도입 순서(온보딩 페이싱) 설계.
- 플레이 시간당 새로운 자극의 밀도를 점검.

### ⚖️ EconomyBalancer (밸런스/경제 설계자)
- 재화 획득·소비 곡선, 성장 커브, 확률 테이블 설계 및 인플레이션/데드록 점검.
- 밸런스 수치는 코드에 흩뿌리지 않고 데이터 파일로 분리해 유효범위(min/max)를 명시 — **이 수치의 검증은 §3 CLI 교차검증 대상**이다.

### 🎨 UIUXDesigner (UI/UX 스페셜리스트)
- 정보 위계, 입력 반응성(입력 지연 체감), 접근성(색약·텍스트 크기), 상태 피드백 설계.
- 플레이어가 지금 무엇을 해야 하는지 한눈에 알 수 있는지 검증.

### 🖌️ ArtDirector (아트 디렉터)
- 비주얼 톤&매너, 팔레트, 애니메이션 원칙(스쿼시/스트레치, 히트스톱) 정의.
- 에셋 규격(해상도/아틀라스/포맷)과 성능 예산 합의 — 실제 화면 검증은 `agy` 멀티모달 리뷰와 짝을 이룬다.

### ⚙️ TechAnalyst (기술 타당성 분석가)
- 렌더링/업데이트 루프, 프레임 예산, 메모리·GC 할당, 로딩 파이프라인 아키텍처 감사.
- 세이브 데이터 스키마 버저닝과 마이그레이션 전략, 플랫폼 이식성 정의.

### 🧪 QAEngineer (품질 보증 엔지니어)
- 재현 절차가 있는 버그 리포트 규격, 회귀 테스트 시나리오, 결정론적 리플레이(시드 고정) 설계.
- "고쳤다"의 판정 기준을 수정 전에 먼저 정의한다.

## 2. 실행 및 구현 에이전트 (Core & Browser)

### 🌌 Core Agent (메인 코딩 에이전트, 현재 세션)
- 기획/아키텍처 명세에 부합하는 실제 소스 코드 구현.
- 테스트·시뮬레이션(밸런스 시뮬, 결정론적 리플레이) 스크립트 설계 및 검증.
- 화면 시각 검증은 브라우저 서브에이전트에게 위임.

### 🌐 Browser Subagent (브라우저 서브에이전트)
- 게임 화면 레이아웃, 입력 반응, 반응형/해상도 대응을 실제로 띄워 확인.
- 스크린샷 캡처 후 아트/UX 가이드라인과 대조하고 기록을 아티팩트에 저장.

## 3. 코드 품질·스펙 동기화·비주얼 패리티 감사 도구 (실제 독립 CLI 3종)

### 🤖 Claude Code CLI — Game Logic & Security Reviewer
- 게임 로직 정확성, 상태 동기화/경쟁 조건, 세이브 데이터 정합성, 시크릿 하드코딩 심사.
```bash
git diff | claude -p "게임 로직 정확성, 상태 동기화/세이브 데이터 정합성, 밸런스 데이터 유효범위, 성능(프레임/GC/할당), 시크릿 하드코딩 여부 리뷰" --allowedTools "Read"
```
`npm run review:code`로 등록됨. 대사/내러티브 톤 검증은 `--model claude-fable-5`로 별도 세션 교차검증.

### 📖 Codex CLI — Specification Sync Reviewer
- `AGENTS.md`, `docs/design.md`, `docs/deploy.md`의 기획·밸런스·배포 규칙과 실제 코드 대조(프롬프트의 단일 출처는 `scripts/review.js`의 `DOC_SYNC_PROMPT`).
```bash
npm run review:docs   # scripts/review.js가 프롬프트/타임아웃/fail-open을 소유
```
`npm run review:docs` / `npm run review:write`로 등록됨.

### 🌌 Antigravity CLI (`agy`) — Visual Parity Reviewer
- 이 프로젝트에서 편의상 "Gemini CLI"라고 부르는 도구는 실제로는 `agy`(Antigravity CLI) 바이너리이며 `--model gemini-3.1-pro-high`로 Gemini 백엔드를 헤드리스 호출한다. 이 머신에 별도 `gemini` 실행 파일은 없다(2026-09-03 확인).
- 게임 화면 스크린샷을 아트/UX 가이드라인과 대조해 정보 위계·색 사용·여백·가독성 편차를 지적한다. trading 프로젝트에서는 가이드라인 문서가 없어 이 역할을 비활성 상태로 뒀지만, 게임은 비주얼이 산출물의 핵심이므로 `docs/design.md`에 비주얼 가이드라인이 채워지는 시점부터 **필수 게이트**로 승격한다.
```bash
agy -p "이 스크린샷을 docs/design.md 비주얼 가이드라인과 대조해 정보 위계/색상/여백/가독성 편차를 지적" --model gemini-3.1-pro-high
```

## 4. 운영 프로세스 가이드라인

1. **기획 단계**: PMOrchestrator + 7인 패널(§1)이 dialogue 형태로 의견을 취합.
2. **구현 단계**: Core Agent가 구현하고, Browser Subagent로 화면을 시각 검증.
3. **리뷰 및 커밋 단계**: 자동 게이트(pre-commit/CI)는 Claude(로직/보안) + Codex(스펙 정합성) **2종**을 돌린다. 3종 전체 교차검증이 필요한 작업(버그 원인분석, 세이브 스키마 변경)은 자동 게이트가 대신해 주지 않으므로 `npm run panel`로 직접 기동해야 한다 — 어느 단계에 몇 종을 쓰는지는 AGENTS.md §4의 표가 단일 출처다. 어느 경우에도 가상 페르소나로 대체하지 않는다.
4. **세이브 데이터 안전장치**: 세이브 스키마 변경은 (a) TechAnalyst + QAEngineer 페르소나 검토, (b) 3종 CLI 교차검증, (c) 구버전 세이브 로드 회귀 테스트를 모두 통과한 뒤에만 반영한다. 마이그레이션은 항상 역방향 손실 여부를 명시한다.
